# Codex Project Instructions

When the user asks for authorized Hack The Box or comparable lab work, load and follow `skills/hackthebox-codex/SKILL.md`. Load only the detailed reference relevant to the current mode: `machine-playbooks.md`, `challenge-playbooks.md`, `sherlock-playbooks.md`, `forensics-and-malware.md`, `ad-and-windows.md`, `web-application.md`, `privilege-escalation.md`, `pivoting-and-ssh.md`, `exploit-review.md`, `tooling-and-output.md`, or `nimux-usage.md`.

Inspect local repositories and artifacts before proposing network activity. Write helper programs to files, review them before execution, use explicit targets and timeouts, capture stdout and stderr, and preserve immutable raw evidence.

Confirm the exact HTB target, scope, objective, and constraints before any network action. Keep work limited to the stated lab target. Do not silently change targets, ports, credentials, or privilege assumptions.

Do not perform denial-of-service, destructive testing, credential spraying, persistence, malware deployment, mass exploitation, or unrelated data collection. Ask before broadening scope, executing unreviewed code obtained from a target, deploying pivots, changing directory or service state, or handling sensitive artifacts beyond what is necessary for the lab objective. Do not scrape, reproduce, summarize, or compile protected HTB content into an AI dataset or knowledge base, and do not publish active solutions.

If the request is ambiguous, ask a concise clarifying question instead of guessing an address, port, credential, flag format, or privilege assumption.
